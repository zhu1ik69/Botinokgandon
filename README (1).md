# Бот-уведомитель об изменении расписания (3РПУ-24-1)

Бесплатный способ запустить это **без компьютера** — через GitHub Actions.
GitHub сам, по расписанию, будет заходить на сервер, качать файл, сравнивать
и слать сообщение в Telegram. Ваш ПК и телефон при этом могут быть выключены.

## Шаги настройки (10–15 минут, один раз)

1. **Замените токен бота.** Вы прислали токен открытым текстом — на всякий
   случай зайдите в @BotFather → `/mybots` → ваш бот → `Bot Settings` →
   `Revoke current token`, получите новый.

2. **Узнайте CHAT_ID чата**, куда бот будет писать:
   - Добавьте бота в нужный чат/группу (и сделайте админом, если это группа).
   - Отправьте в этот чат любое сообщение.
   - Откройте в браузере:
     `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
   - В ответе найдите `"chat":{"id": -100123456789, ...}` — это и есть CHAT_ID
     (для групп обычно отрицательное число).

3. **Создайте репозиторий на GitHub** (github.com → New repository, можно
   приватный — Actions бесплатны и для приватных репозиториев в пределах
   бесплатного лимита минут, а для публичных вообще без ограничений по
   минутам).

4. Загрузите в репозиторий два файла из этого чата:
   - `check_schedule.py` — в корень репозитория
   - `check.yml` — в папку `.github/workflows/check.yml`
     (можно прямо через веб-интерфейс GitHub: "Add file" → "Create new file",
     указав путь `.github/workflows/check.yml`)

5. **Добавьте секреты** (репозиторий → Settings → Secrets and variables →
   Actions → New repository secret):
   - `BOT_TOKEN` — новый токен бота
   - `CHAT_ID` — chat_id из шага 2

6. Зайдите во вкладку **Actions** репозитория, найдите workflow
   "Check schedule" и один раз запустите его вручную кнопкой
   **"Run workflow"** — это первый запуск, он просто запомнит текущее
   состояние файла и ничего не пришлёт.

Дальше всё работает само: каждые 15 минут GitHub скачивает файл,
сравнивает с прошлой версией и, если она изменилась — присылает
сообщение в ваш чат со ссылкой на актуальное расписание.

## Настройки, которые можно поменять

- Частота проверки — строка `cron: "*/15 * * * *"` в `check.yml`
  (минимум, который поддерживает GitHub, — раз в 5 минут: `*/5 * * * *`;
  учтите, что расписание GitHub Actions best-effort и может слегка
  запаздывать при высокой нагрузке).
- Текст уведомления — в файле `check_schedule.py`, функция `send_telegram_message`.

## Альтернативы GitHub Actions (тоже бесплатно, без ПК)

- **PythonAnywhere** (free-тариф) — Bash/Python-консоль в браузере + Scheduled
  Tasks, но на бесплатном плане задачи можно ставить не чаще раза в день,
  так что для частой проверки расписания GitHub Actions подходит лучше.
- **Render.com** — есть бесплатные Cron Jobs, тоже вариант, но регистрация
  чуть более многошаговая, чем на GitHub.
